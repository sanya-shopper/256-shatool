Notation. ⊞ is addition modulo 2³², ⊕ exclusive or, ∧ and, ¬ complement. ROTRⁿ rotates a 32-bit word right by n, SHRⁿ shifts it right by n and fills with zeros. Every value below is one 32-bit word.

Seeding the window, at t = 0

A[−1] = H[0]   A[−2] = H[1]   A[−3] = H[2]   A[−4] = H[3]
E[−1] = H[4]   E[−2] = H[5]   E[−3] = H[6]   E[−4] = H[7]

These eight words are the incoming chaining value, and they are the four columns left of the dashed rule on each of the A and E bands. Note the reversal: the more negative the index, the later the H. It follows from a = A[t−1], b = A[t−2], c = A[t−3], d = A[t−4] read at t = 0.

Term order. Every sum below is written with the plain terms first — the schedule word, the round constant, and whichever earlier A or E enters unchanged — and the compound expressions last. Addition modulo 2³² is commutative and associative, so the order is a presentation choice and nothing more; it is chosen so each line starts with what is simply carried in and ends with what is computed.

The round, as usually written

T1[t] = W[t] ⊞ K[t] ⊞ E[t−4] ⊞ Σ1(E[t−1]) ⊞ Ch(E[t−1],E[t−2],E[t−3])
T2[t] = Σ0(A[t−1]) ⊞ Maj(A[t−1],A[t−2],A[t−3])
E[t]  = A[t−4] ⊞ T1[t]
A[t]  = T1[t] ⊞ T2[t]

With T1 and T2 substituted out

E[t] = W[t] ⊞ K[t] ⊞ A[t−4] ⊞ E[t−4]
              ⊞ Σ1(E[t−1]) ⊞ Ch(E[t−1],E[t−2],E[t−3])

A[t] = W[t] ⊞ K[t] ⊞ E[t−4]
              ⊞ Σ1(E[t−1]) ⊞ Ch(E[t−1],E[t−2],E[t−3])
              ⊞ Σ0(A[t−1]) ⊞ Maj(A[t−1],A[t−2],A[t−3])

The two differ by exactly two terms: E takes A[t−4], A takes Σ0 ⊞ Maj. That single A[t−4] is the only path from the A track to the E track in the whole function.

With the named functions substituted out too

E[t] = W[t]
     ⊞ K[t]
     ⊞ A[t−4]
     ⊞ E[t−4]
     ⊞ (ROTR⁶(E[t−1]) ⊕ ROTR¹¹(E[t−1]) ⊕ ROTR²⁵(E[t−1]))
     ⊞ ((E[t−1] ∧ E[t−2]) ⊕ (¬E[t−1] ∧ E[t−3]))

A[t] = W[t]
     ⊞ K[t]
     ⊞ E[t−4]
     ⊞ (ROTR⁶(E[t−1]) ⊕ ROTR¹¹(E[t−1]) ⊕ ROTR²⁵(E[t−1]))
     ⊞ ((E[t−1] ∧ E[t−2]) ⊕ (¬E[t−1] ∧ E[t−3]))
     ⊞ (ROTR²(A[t−1]) ⊕ ROTR¹³(A[t−1]) ⊕ ROTR²²(A[t−1]))
     ⊞ ((A[t−1] ∧ A[t−2]) ⊕ (A[t−1] ∧ A[t−3]) ⊕ (A[t−2] ∧ A[t−3]))

Nothing is hidden in a name any more. Every round is these two sums, and the whole of SHA-256's compression is running them for t = 0 … 63. The first four lines of each are carried in unchanged; only the last two or four do any mixing.

The message schedule

W[t] = the block's t-th 32-bit word, big-endian            0 ≤ t < 16

W[t] = W[t−16]
     ⊞ W[t−7]
     ⊞ (ROTR⁷(W[t−15]) ⊕ ROTR¹⁸(W[t−15]) ⊕ SHR³(W[t−15]))
     ⊞ (ROTR¹⁷(W[t−2]) ⊕ ROTR¹⁹(W[t−2]) ⊕ SHR¹⁰(W[t−2]))   16 ≤ t < 64

The schedule depends only on the block, never on the chaining value — which is why the W band looks the same whatever precedes it, and why it is computed for all 64 rounds even when the round limit is lower.

Feed-forward, leaving the block

H′[0] = H[0] ⊞ A[63]   H′[1] = H[1] ⊞ A[62]
H′[2] = H[2] ⊞ A[61]   H′[3] = H[3] ⊞ A[60]
H′[4] = H[4] ⊞ E[63]   H′[5] = H[5] ⊞ E[62]
H′[6] = H[6] ⊞ E[61]   H′[7] = H[7] ⊞ E[60]

The final four-wide window of each track, added to the value that seeded it. This is the one step that is not invertible, and it is what stops the compression function from being run backwards. With the round limit at r, read A[r−1 … r−4] and E[r−1 … r−4] instead.

Reading order. Bitcoin treats these 32 bytes as a little-endian 256-bit integer, so byte 31 — the last one SHA-256 emits — is the most significant, and byte 0 is the least. The conventional block-hash string is this digest written backwards, which is why its zeros appear at the front.

What this is not. Bitcoin hashes an 80-byte block header with SHA-256 applied twice. shatool applies it once to an arbitrary message, so the digest above is not a block hash and the verdict is not a claim about mining. What is exactly true is the part shown: given any 32 bytes, this is the weight each byte carries in the difficulty comparison and this is how the comparison comes out.
